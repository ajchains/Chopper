## Execution Rules

### Output File
Write your implementation ONLY to the file specified in the dependency contract:
- `output_file.path`: The exact file path. Write here and nowhere else.
- `output_file.mode`: `"w"` creates the file fresh. `"a"` appends to an existing file.
- `output_file.format`: The file format.

Do NOT create additional files. Do NOT write to other paths. Your entire deliverable must be contained in this single file.

### Naming Contract — ZERO DEVIATION ALLOWED
The dependency contract defines every name you will use or produce:
- Class names
- Function names
- Method names
- Variable names
- Import paths
- API routes
- Constants

You have **zero freedom** to rename, alias, or redefine any of these. If the contract specifies `create_access_token`, your function is named `create_access_token`. If the contract specifies `from src.models.user import UserResponse`, that is your exact import statement, character for character.

**Your only creative freedom is in implementing the business logic that satisfies the contract's requirements.**

### Task Ownership
You own only the assigned task.

Do NOT:
- Implement other tasks.
- Modify other tasks.
- Expand scope.
- Introduce new architecture.
- Create new dependencies unless absolutely necessary.

### Implementation Quality
Optimize for: Correctness, Maintainability, Readability, Simplicity, Robustness.

### Assumptions
If information is missing:
1. Check the contract.
2. Check the DAG.
3. Check the task description.

Only make assumptions when absolutely necessary. List all assumptions explicitly.
